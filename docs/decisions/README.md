# Decisões

Toda decisão arquitetural relevante é registrada aqui. Enquanto está pendente, fica nesta lista
com as alternativas e a recomendação. Depois de aprovada, entra em um ADR nesta pasta
(`NNNN-titulo.md`, com contexto, decisão e consequências). Decisões aprovadas em conjunto podem
dividir o mesmo ADR.

Status possíveis: **pendente**, **aprovada**, **recusada**, **substituída**.

Aprovadas: D-01 a D-10 (2026-11-23, [ADR 0001](0001-fundacao.md)); D-11 a D-15 e D-30 a D-33
(2026-11-24, [ADR 0002](0002-autenticacao.md)); D-34 (2026-11-25, ADR 0002); D-16 a D-23 e D-35
a D-39 (2026-11-25, [ADR 0003](0003-nucleo-financeiro.md)). As demais estão **pendentes**. A alternativa
recomendada vem primeiro.

| D-11 | Chave de `profiles`             | **`profiles.id` é o próprio `auth.users.id`; sem coluna `user_id`** · manter `id` e `user_id`                                                                      | Remove a redundância (C-01). | D-14 | Exclusão de conta e exportação  | **Exclusão na Fase 1, com exclusão definitiva em cascata; exportação na Fase 6** · ambas na Fase 8                                                                 | A exclusão é trivial enquanto só existe `profiles`, e cada tabela nova já nasce com `on delete cascade`.                                                                                                                                                              |
| D-15 | Auditoria e consentimento       | **Tabela `audit_events` (só inserção, sem valores) na Fase 1; tabela `consents` apenas se alguma base legal for consentimento** · usar só os logs do Supabase Auth | Os logs do Auth cobrem login e logout, não os eventos de movimentação exigidos no §6.4.                                                                                                                                                                               |
| D-30 | CSP                             | **Desligar Cache Components e usar CSP com nonce por requisição** · manter Cache Components e a CSP atual, que permite script inline                               | A CSP atual quase não protege contra XSS. Toda tela com dado financeiro já é renderizada por requisição, então a perda de desempenho é pequena. Custo: sair do padrão do Next.js 16. Mais barato decidir antes de existirem telas. Ver [SECURITY.md](../SECURITY.md). |
| D-31 | Criação do perfil               | **Gatilho no banco, na criação do usuário (única função `SECURITY DEFINER` do projeto)** · criar o perfil pela aplicação no primeiro login                         | O gatilho é atômico: não existe conta sem perfil. A alternativa evita privilégio elevado, mas deixa um intervalo em que a conta existe sem perfil.                                                                                                                    |
| D-32 | Cliente Supabase no navegador   | **Não usar; autenticação só por Server Action e cookie de sessão `httpOnly`** · manter o cliente de navegador para fluxos de autenticação                          | O JavaScript da página deixa de enxergar o token de sessão e a CSP deixa de liberar conexão com o Supabase. Depende de o `@supabase/ssr` aceitar o cookie `httpOnly`, a validar na implementação.                                                                     |
| D-33 | Política de senha               | **Mínimo de 12 caracteres, sem regra de composição** · padrão do Supabase (6 caracteres) · mínimo de 8 com regra de composição                                     | Comprimento protege mais que composição e é mais fácil de cumprir com gerenciador de senhas. A verificação de senha vazada depende do plano do Supabase (D-29).                                                                                                       |

Aprovadas em 2026-11-25 ([ADR 0003](0003-nucleo-financeiro.md)). Em cada linha, a alternativa

## Bloqueiam a Fase 4

| ID   | Decisão                         | Proposta a confirmar                                                                                                                                                                                                                                                                                                                                                                                                             |
| ---- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-24 | Fórmulas                        | Saldo do período = receitas − despesas efetivadas. Capacidade de poupança = renda planejada − despesas fixas − variáveis planejadas. Margem restante = capacidade de poupança − reserva planejada. Com o exemplo do Módulo 06: 6.500 − 2.500 − 1.500 = 2.500 e 2.500 − 1.000 = 1.500. **"Capacidade de investimento" precisa de definição do proprietário**: o exemplo do Módulo 02 (R$ 800) não é derivável dos outros números. |
| D-25 | Dívidas, compromissos e reserva | Dívida e compromisso como despesa recorrente com data de término; reserva planejada como contribuição mensal planejada de uma meta. Alternativa: entidades próprias.                                                                                                                                                                                                                                                             |
| D-26 | Contribuição de meta            | Tabela `goal_contributions`; `current_amount` deixa de ser coluna e passa a ser a soma. Contribuição não é despesa. Alternativa: tratar como transferência para uma conta de reserva.                                                                                                                                                                                                                                            |
